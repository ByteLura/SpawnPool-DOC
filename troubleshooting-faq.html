Troubleshooting & FAQ

Every answer below describes behaviour defined in the product's own documentation and code. If your case is not covered, see the Support & Scope page for how support works.

The dashboard is empty

That is the expected empty state, not an error. Pools appear in the dashboard the moment your game spawns something pooled. Press Play in a scene that pools something — or open the Pool Playground from the welcome block and watch its three pools appear.

Spawn returned null

The pool is at its growth cap. The refusal has been counted in CapHits and warned about once for this pool this session. Your options:

  • raise the cap (set it before the first spawn of that prefab, through GetOrCreatePool, the PoolPreloader entry, or the pool constructor),
  • find the instances being held out too long — LongestCheckoutSeconds and the dashboard's attention strip point at them, or
  • knowingly enable Allow Exceed Cap for that pool if growth is the behaviour you want.

If you need to branch on refusal without a null check, use TrySpawn, which returns false at cap.

My Warnings counter is above zero

A warning means one of these happened, and each one points at calling code worth fixing:

  • Double return — the same instance was returned twice. The second return was ignored and the pool was not corrupted. Look for a duplicate Despawn call, including a delayed despawn racing a manual one — note that a manual despawn before a delayed deadline cancels the schedule, so that pairing on its own does not warn.
  • Foreign return — an instance no pool created was despawned. On the GameObject path it was destroyed and counted. Look for a Despawn call on an object that was never spawned through the pool.

Warnings are logged once per pool and counted per pool, so the dashboard tells you which pool's calling code to inspect.

Created keeps climbing during play

The pool is still creating instances at runtime: spawns are exceeding the stock. Read Peak — the most instances ever active at once — and raise prewarm toward it. The split between ReusedCount and CreatedOnSpawnCount tells you how many spawns were served from stock versus created.

An instance never comes back

Most often a missed Despawn on one code path. Check LongestCheckoutSeconds for the pool and the attention strip in the dashboard, which lists long checkouts with the instance and how long it has been out. Delayed despawns can also be in flight: an instance despawned with a delay stays active until its deadline passes.

OnDespawned cleanup runs, but the object still looks active in it

That is the guaranteed order, not a bug: OnDespawned runs while the instance is still active, before deactivation and parking. OnSpawned is the mirror: the instance is positioned and activated first, then OnSpawned runs. Core Concepts documents the full order.

The driver object — what is it, and can I delete it?

"SpawnPool Pro Driver" is the single hidden object the product creates on first use. It ticks delayed despawns and the checkout clock. You never place it and you do not need to manage it: it is hidden in the hierarchy, repeated creation is guarded, and PoolManager.ClearAll() and application quit destroy it cleanly. If it is missing, it is recreated on next use.

Does SpawnPool Pro work with Addressables content?

There is no Addressables integration in version 1, and the package carries no Addressables dependency. If you instantiate an object from an Addressables handle yourself, you can pool that instance through the normal API. Loading, releasing, and tracking Addressables assets stays your code's job. See Honest Limits.

Does anything get saved, exported, or sent anywhere?

No. Analytics are live and in-memory only. The runtime writes nothing to disk, makes no network calls, and sends no telemetry. When Play Mode stops, the counters stop.

Structs, networking, automatic sizing?

Not in version 1 — the typed pool is for reference types, pools are local to the client, and caps are set by you with the dashboard's numbers to guide you. Honest Limits is the full honest-limits list.

Verify Install reports a problem

Re-import the package, then run Verify Install again from Tools > ByteLura > SpawnPool Pro > Verify Install and read its per-check report in the window's header status line. If a check still fails on a clean import, contact support as described on the Support & Scope page and include the exact per-check wording.
