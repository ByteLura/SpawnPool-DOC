Quick Start

Pool anything. See what it costs. Never pay Instantiate at runtime again.

Your first pooled spawn (about five minutes)

  1. Open Tools > ByteLura > SpawnPool Pro. The welcome block is at the top of the window.
  2. Click Open the Pool Playground. The sample imports and its scene opens.
  3. Press Play. A turret fires pooled projectiles at pooled targets; hits fire pooled sparks.
  4. Look at the SpawnPool Pro window while it plays. Three pools are listed with live counts. Watch the projectile pool: Created stays flat while Spawns climbs. That flat Created counter is the whole promise — reuse instead of runtime Instantiate.
  5. Stop. Drag your own prefab onto the Pool Preloader in the sample scene (or add a Pool Preloader to your own scene), set its prewarm count, and press Play. Your prefab is pooled.

There is no setup step before this flow. You create no folders, no manager objects, and no configuration assets. Pools create themselves on first use, and the one hidden driver object creates itself too.

Pooling from code

using ByteLura.SpawnPool;

// Anywhere — no manager object to place, pools create themselves:
GameObject bullet = PoolManager.Spawn(bulletPrefab, muzzle.position, muzzle.rotation);
PoolManager.Despawn(bullet);                 // back into the pool
PoolManager.Despawn(bullet, 2f);             // ...or after 2 seconds
PoolManager.Prewarm(bulletPrefab, 32);       // create 32 ahead of time

// Know when a pool is full instead of getting null:
GameObject enemy;
if (PoolManager.TrySpawn(enemyPrefab, out enemy)) { /* use it */ }

// Plain C# objects pool too:
var events = new Pool<DamageEvent>(() => new DamageEvent(), maxCapacity: 256);
DamageEvent e = events.Get();
events.Release(e);

Lifecycle callbacks

Add a component implementing IPoolable to a pooled prefab and it hears about every spawn and despawn:

public class Bullet : MonoBehaviour, IPoolable
{
    public void OnSpawned()  { /* reset state here */ }
    public void OnDespawned() { /* tidy up here; the object is still active */ }
}

On despawn, OnDespawned runs before deactivation. On spawn, the instance is positioned and activated before OnSpawned. You can rely on that order — Core Concepts explains the full lifecycle.
