Honest Limits: What Version 1 Is Not

This page expands the WhatV1IsNot page that ships inside the package. Read it before planning around SpawnPool Pro. Everything here is a deliberate scope decision for version 1, stated plainly so your plan never depends on something the product does not do.

Not an Addressables integration

The package has no Addressables dependency. You can pool an object you instantiated from an Addressables handle yourself through the normal API, but SpawnPool Pro does not load, release, or track Addressables assets for you.

Not a networking solution

Pools are local to this client. Networked games pool their local visuals and effects; spawn authority stays with your netcode.

Not an analytics history tool

Counters are live and in-memory. Nothing is saved to disk, exported, or graphed over time; when Play Mode stops, the numbers stop. Nothing about your project leaves your machine — the product makes no network calls and sends no telemetry.

Not self-tuning

Caps and prewarm counts are yours to set. The dashboard shows you exactly the numbers to tune them with — Peak tells you the prewarm a pool actually needs — but the product does not resize pools on its own.

Not a struct pool

The typed pool covers reference types (classes). The same pattern works for structs, but a struct pool is not shipped in version 1.

Not render-pipeline specific

The runtime is render-pipeline agnostic and makes no pipeline claims.

The exact scope of the allocation statement

The hot-path statement covers Spawn and Despawn — and typed Get and Release — after prewarm. It does not cover:

  • setup and first creation (creating an instance the first time is real work, done once),
  • prewarm itself,
  • building PoolStats snapshots, which happens on demand when you or the dashboard reads them, or
  • editor window drawing.

Copy anywhere that implies allocation-free behaviour outside that scope would be wrong, and this product does not make that claim.

No persistent settings in version 1

There is no settings asset and no configuration file. The only stored preference is the window's own "Show welcome on open" toggle, kept in editor preferences. Teardown is Clear All Pools — there is nothing else to reset because there is nothing else stored.
