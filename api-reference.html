API Reference Summary

All types live in the ByteLura.SpawnPool namespace. This page summarizes the API reference that ships inside the package (Documentation~/ApiReference.md); that shipped file is the canonical version.

PoolManager (static)

The front door for GameObject pooling. One pool per prefab, created on first use. There is no manager object to place in a scene.

  • Spawn(GameObject prefab) — spawn at the prefab's own position and rotation. Null at cap.
  • Spawn(GameObject prefab, Vector3 position, Quaternion rotation, Transform parent = null) — spawn placed. Null at cap.
  • Spawn<T>(T componentPrefab) — spawn a component prefab; returns the component. Null at cap.
  • TrySpawn(GameObject prefab, out GameObject instance) — non-throwing spawn; false at cap.
  • Despawn(GameObject instance) — return an instance to its pool. Foreign instances are destroyed and counted as warnings.
  • Despawn(GameObject instance, float delaySeconds) — delayed despawn via the single hidden driver. A manual despawn before the deadline cancels it.
  • GetOrCreatePool(GameObject prefab, int maxCapacity = 0, bool allowExceedCap = false) — get or create the pool for a prefab; call before first spawn to set caps.
  • Prewarm(GameObject prefab, int count) — create inactive instances ahead of time.
  • TryGetStats(GameObject prefab, out PoolStats stats) — snapshot for a prefab's pool; false if no pool exists yet.
  • ClearAll() — destroy every pooled instance, the pool root, and the driver.

GameObjectPool

Own one directly when you want explicit control instead of the static facade.

  • Constructor: GameObjectPool(GameObject prefab, int initialCapacity = 0, int maxCapacity = 0, bool allowExceedCap = false, Transform root = null).
  • Spawn() / Spawn(Vector3, Quaternion, Transform) / TrySpawn(out GameObject, Vector3, Quaternion, Transform) — same semantics as PoolManager.
  • Despawn(GameObject), Prewarm(int), Clear(), Stats, Prefab, ActiveCount, InactiveCount.

Pool<T> — typed pool for plain C# objects

  • Constructor: Pool(Func<T> factory, Action<T> resetOnRelease = null, int initialCapacity = 0, int maxCapacity = 0, bool allowExceedCap = false).
  • Get() returns an instance, or null at the cap. TryGet(out T) is the non-throwing form.
  • Release(T) returns an instance. Double releases and foreign releases are detected, counted in Stats.Warnings, and ignored — the pool is never corrupted by misuse.
  • Prewarm(int), Clear(), Stats, ActiveCount, InactiveCount.

PoolStats

A snapshot struct: PoolName, ActiveCount, InactiveCount, TotalCreated, PeakActive, SpawnCount, DespawnCount, ReusedCount, CreatedOnSpawnCount, CapHits, OverflowCreates, Warnings, LongestCheckoutSeconds, and ReuseRatio (0 to 1). Snapshots are built on demand; reading them is never part of the hot path.

PoolAnalytics (static)

  • PoolCount — registered pools.
  • GetAllStats(List<PoolStats> results) — fills your list with one snapshot per pool (the list is cleared and reused).
  • TotalWarnings — warnings across all pools plus pool-less warnings.

PoolPreloader (component)

Add to any scene object; list (prefab, prewarm count, max capacity, allow exceed cap) entries. Prewarms in Awake by default, or call PrewarmNow() yourself. Repeated calls only top up.

IPoolable

  • OnSpawned() runs after positioning and activation.
  • OnDespawned() runs while the instance is still active, before deactivation and parking.
  • Callbacks are collected from the instance and its children once, at creation.

Semantics you can rely on

  • FIFO reuse: the longest-inactive instance is handed out first.
  • Cap behaviour: at cap, spawns refuse (null / false), the refusal is counted in CapHits, and a warning is logged once per pool per session. Pools never silently exceed a cap unless created with Allow Exceed Cap.
  • Hot path: after prewarm, Spawn/Despawn — and typed Get/Release — perform no managed allocation in the shipped automated test on Unity 6000.5.4f1 and Unity 2022.3.22f1.
  • Checkout ages are measured on the driver clock (unscaled time) and reported as LongestCheckoutSeconds.
  • Errors are warnings with counters, never exceptions across the game loop. The exception is setup-time constructor argument validation, which throws the standard argument exceptions at setup time only.
