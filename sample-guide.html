Sample Guide: Pool Playground

What the sample is

A turret, its projectiles, the targets, and the hit sparks — everything on screen is pooled. The Pool Playground is the fastest way to see the product's promise with your own eyes: reuse instead of runtime Instantiate, proven by a counter that stays flat.

Run it

  1. Open the PoolPlayground scene — the welcome block's Open the Pool Playground action imports the sample and opens the scene for you.
  2. Open Tools > ByteLura > SpawnPool Pro and keep the window visible.
  3. Press Play.

What to watch

  • The turret sweeps and fires. Every projectile is a reused pool instance: in the dashboard, the projectile pool's Created counter stays flat while Spawns climbs.
  • Targets pop with a pooled spark and are replaced by the field — again from the pool, not from Instantiate.
  • The board in the scene shows the same counters the dashboard shows, read from PoolAnalytics.

How it is wired

  • Pool Preloader (on the "Pool Setup" object) prewarms all three prefabs — no code, no manager object placed by hand.
  • PlaygroundTurret spawns through PoolManager.Spawn and arms each projectile with Launch.
  • PlaygroundProjectile and PlaygroundTarget implement IPoolable to reset themselves on spawn and tidy up on despawn.
  • PlaygroundField manages the target field and its replacements.
  • PooledLifetime gives the sparks their short life, despawning through the same public API.
  • PlaygroundHud draws the on-screen live counts, read from PoolAnalytics — the same data the dashboard shows.
  • Every script in the sample uses only the public SpawnPool Pro API — the same calls your game would make. The sample has its own assembly that references the Runtime assembly only.

Make it yours — the two-minute experiment

  1. Stop Play Mode.
  2. Drag your own prefab onto the Pool Preloader in the sample scene, or add an entry for it, and set a prewarm count.
  3. Press Play and find your prefab's pool in the dashboard.

Your prefab is now pooled, with its counts on screen. That is the whole adoption path: there is no other integration step.

What the sample deliberately does not do

  • It does not use any internal or editor-only API — if the sample can do it, your game code can do it the same way.
  • It carries no extra dependencies: its on-screen text uses built-in Unity UI with the default font, keeping the package dependency-free.
